# Plan 05-02: Comparative QoS Benchmarking Pipeline & Triad Evaluation

## Objective
Build and execute the automated comparative QoS benchmarking pipeline (`scripts/run_closed_loop_benchmark.py`). Run the 3-way triad comparison (Baseline AODV vs. Attack AODV vs. AODV+IDS) across Blackhole and Grayhole attacks on 30-node and 50-node topologies under identical simulation seeds (42, 43, 44). Quantitatively verify Packet Delivery Ratio (PDR) recovery, measure throughput and delay impacts, evaluate the routing overhead cost penalty, export structured result artifacts (`results/closed_loop_metrics.csv`, `results/closed_loop_report.md`, `results/isolation_events.csv`), and validate the entire evaluation via automated integration tests.

---

<threat_model>
ASVS Level: 1
Threat ID: T-05-05 (Non-Deterministic Evaluation Bias)
Description: Running Baseline, Attack, and AODV+IDS under differing initial seeds or random sequences creates false impressions of QoS recovery or misattributes mobility link breaks to IDS mitigation.
Mitigation: Enforce paired-seed determinism: Each triad scenario row MUST execute all three modes (`Baseline`, `Attack`, `AODV+IDS`) using the exact same random seed. The runner strictly validates seed matching across each comparison triad before computing recovery deltas.

Threat ID: T-05-06 (Reporting Inversion & Metric Tampering)
Description: Negative QoS impacts or excessive routing overhead penalties are masked or omitted, presenting a biased view of IDS efficacy.
Mitigation: Mandate comprehensive unrounded float calculations for all standard QoS metrics (PDR, Throughput, Average Delay, Packet Loss Ratio, Routing Overhead) and both recovery metrics:
1. Absolute PDR Recovery: $\Delta\text{PDR}_{\text{abs}} = \text{PDR}_{\text{AODV+IDS}} - \text{PDR}_{\text{Attack}}$
2. Recovery Ratio (% of lost baseline PDR recovered):
   $$\text{Recovery Ratio} = \frac{\text{PDR}_{\text{AODV+IDS}} - \text{PDR}_{\text{Attack}}}{\text{PDR}_{\text{Baseline}} - \text{PDR}_{\text{Attack}}} \times 100\%$$
3. Routing Overhead Cost: $\Delta\text{OH} = \text{OH}_{\text{AODV+IDS}} - \text{OH}_{\text{Baseline}}$.
All three metrics are explicitly exported to both the CSV table and Markdown report.
</threat_model>

Implement the automated triad benchmark orchestrator in `scripts/run_closed_loop_benchmark.py`:

1. Scenario Matrix Configuration (Decision D-14):
   Define the 4 primary benchmark scenarios:
   - `30n_blackhole`: Base scenario `scenarios/e2_blackhole_30n.json` (`attack.type = "Blackhole"`, `attack.enabled = True`).
   - `30n_grayhole_p50`: Base scenario with `attack.type = "Grayhole"`, `attack.drop_prob = 0.5`.
   - `30n_grayhole_p70`: Base scenario with `attack.type = "Grayhole"`, `attack.drop_prob = 0.7`.
   - `50n_grayhole_p50`: Base scenario `scenarios/e4_grayhole_50n.json` (`attack.type = "Grayhole"`, `attack.drop_prob = 0.5`).
   Seeds: `[42, 43, 44]`.

2. Triad Modes per Scenario & Seed:
   For each (scenario, seed) combination, execute 3 simulation runs:
   - Mode `Baseline`:
     `cfg["attack"]["enabled"] = False`
     `cfg["ids"] = {"enabled": False}`
   - Mode `Attack`:
     `cfg["attack"]["enabled"] = True`
     `cfg["ids"] = {"enabled": False}`
   - Mode `AODV+IDS`:
     `cfg["attack"]["enabled"] = True`
     `cfg["ids"] = {"enabled": True, "threshold": 0.50, "window_size": 5.0, "quarantine_duration": 30.0, "strikes_required": 2}`

3. Metric Calculation & Recovery Deltas:
   Calculate standard metrics via `compute_metrics(runner.trace_rows, sim_duration)`:
   - `pdr`, `throughput_bps`, `avg_delay_s`, `packet_loss_ratio`, `routing_overhead`.
   After obtaining triad metrics for identical seed:
   - `delta_pdr_abs = pdr_ids - pdr_attack`
   - `recovery_ratio`:
     If `pdr_baseline > pdr_attack`:
       `recovery_ratio = (pdr_ids - pdr_attack) / (pdr_baseline - pdr_attack) * 100.0`
     Else:
       `recovery_ratio = 100.0`
   - `overhead_cost = overhead_ids - overhead_baseline`

4. Dual Export & Reporting:
   - Output `results/closed_loop_metrics.csv` with columns:
     `scenario,nodes,attack_type,drop_prob,seed,mode,pdr,throughput_kbps,avg_delay_ms,packet_loss_ratio,routing_overhead,delta_pdr_abs,recovery_ratio,overhead_cost`
   - Output `results/closed_loop_report.md` with:
     - Executive summary of closed-loop IDS mitigation performance.
     - Formatted Markdown tables presenting side-by-side triad metrics (Baseline vs Attack vs AODV+IDS) averaged across seeds 42, 43, 44.
     - Breakdown of PDR recovery ratios and routing overhead costs.
     - Key findings explaining how AODV route rediscovery routes around isolated nodes.
   - Output `results/isolation_events.csv` consolidating all quarantine alerts across all `AODV+IDS` runs.

5. CLI Arguments:
   - `--smoke`: Runs a single seed (42) on 30n Blackhole for rapid testing and verification.
   - `--seeds`: List of integer seeds (default: 42, 43, 44).
   - `--out-dir`: Destination directory for reports and metrics (default: `results`).
   - `--duration`: Optional scenario duration override (e.g. 100.0s for quicker test execution).
