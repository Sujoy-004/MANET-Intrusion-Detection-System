<threat_model>
- Label & Identity Leakage: Including `node_id`, `is_attacker`, `dropped_by`, coordinates, or timestamps in feature columns allows ML models to memorize malicious identities rather than learning traffic behavioral anomalies. Feature matrix $X$ must strictly contain only the 9 behavioral features.
- Division-by-Zero / NaN Corruption: Inactive nodes that forward zero packets produce `0 / 0` division errors. Per D-07, neutral fallbacks (`packet_forward_ratio = 1.0`, `packet_drop_ratio = 0.0`) must be assigned to avoid `NaN` values that break ML estimators.
- Future-Peeking / Temporal Leakage: Aggregating features over time intervals that extend forward from $t$ exposes future events to current decisions. Windows must strictly aggregate backward: $t - W \le t_{event} \le t$.
</threat_model>

  </read_first>
  <behavior>
    - Accepts `--trace <csv>`, `--scenario <json>`, `--out <csv>`, with optional `--window` (default 5.0), `--step` (default 1.0), `--warmup` (default 10.0), `--min-packets` (default 0).
    - Aggregates events backward in time: $[t - W, t]$ for $t = \text{warmup}, \text{warmup} + \text{step}, \dots \le T_{max}$.
    - For each node $i$ in window $[t - W, t]$:
      1. `packet_forward_ratio`: `FWD / (FWD + DROP)`. If `FWD + DROP == 0`, assign `1.0` (D-07).
      2. `packet_drop_ratio`: `DROP / (FWD + DROP)`. If `FWD + DROP == 0`, assign `0.0` (D-07).
      3. `avg_delay`: mean end-to-end delay $(t_{recv} - t_{sent})$ of delivered packets terminating at node $i$ or traversing node $i$ within window. If none, assign `0.0`.
      4. `route_request_rate`: count of RREQ events where `node_id == i` divided by $W$ (Hz).
      5. `route_reply_rate`: count of RREP events where `node_id == i` divided by $W$ (Hz).
      6. `throughput`: `count(DATA_RECV where node_id == i) * 512 * 8 / W` (bps).
      7. `hop_count`: mean `hop_count` of packets handled by node $i$ in window. If none, assign `0.0`.
      8. `neighbor_count`: mean `neighbor_count` from `NODE_STATUS` events for node $i$ in window. If missing, use latest known status or `0.0`.
      9. `mobility_speed`: mean `speed` from `NODE_STATUS` events for node $i$ in window. If missing, use latest known status or `0.0`.
      10. `label`: string `"Blackhole"` if node $i \in \text{attackers}$, else `"Normal"`. Derived strictly from scenario metadata.
    - Exactly 10 columns in output CSV in the exact required order. Zero `NaN` or `inf` values.
  </behavior>
  <action>
1. Create `feature_extraction/__init__.py` exposing `extract_features_from_trace`.
2. Create `feature_extraction/extract_features.py`:
   - Define `SCHEMA_COLUMNS = ["packet_forward_ratio", "packet_drop_ratio", "avg_delay", "route_request_rate", "route_reply_rate", "throughput", "hop_count", "neighbor_count", "mobility_speed", "label"]`.
   - Implement `extract_features_from_trace(trace_df: pd.DataFrame, scenario_config: Dict[str, Any], window_size: float = 5.0, step_size: float = 1.0, warmup: float = 10.0, min_packets: int = 0) -> pd.DataFrame`.
   - Parse attacker nodes list from `scenario_config.get("attack", {})`. Support dynamic attacker extraction if stored in scenario or metadata.
   - Match sent and received data packets by `pkt_id` to establish per-packet end-to-end delays.
   - For each time step $t$ from `warmup` to `trace_df["time"].max()` by `step_size`:
     Slice window events: `window_df = trace_df[(trace_df["time"] >= t - window_size) & (trace_df["time"] <= t)]`.
     For each node $i$ in `all_nodes`:
       Compute the 9 behavioral features using vectorization or grouped lookups.
       Apply neutral baseline forward/drop ratio (`1.0` / `0.0`) when `FWD + DROP == 0`.
       Filter out rows if `total_packets < min_packets`.
       Assign `label = "Blackhole"` if `node_id in attacker_nodes` else `"Normal"`.
   - Return DataFrame containing strictly `SCHEMA_COLUMNS`.
   - Implement CLI `parse_args` and `main` using standard `argparse` (`--trace`, `--scenario`, `--out`, `--window`, `--step`, `--warmup`, `--min-packets`).
3. Create `tests/test_feature_pipeline.py`:
   - Unit test asserting output DataFrame columns match `SCHEMA_COLUMNS` exactly.
   - Test checking neutral forward ratio (`1.0`) and drop ratio (`0.0`) on idle nodes.
   - Test verifying zero `NaN` or `inf` entries in generated feature matrix.
  </action>
