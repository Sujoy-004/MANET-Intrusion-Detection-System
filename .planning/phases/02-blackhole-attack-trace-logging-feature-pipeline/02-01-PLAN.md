<objective>
Implement the decoupled RFC 3561 Blackhole attack strategy and the dynamic flow-intercept attacker placement algorithm.

Purpose: Deliver adversarial routing behavior (ATK-01) where:
- D-01: Dynamic flow-intercept placement selects an intermediate node along active CBR paths (excluding endpoints).
- D-02: Configurable spoofed RREP parameters allow the malicious node to advertise false maximum sequence numbers (+1000) and 1-hop distance to attract legitimate traffic.
- D-03: Silent intercepted data drop causes the attacker to drop 100% of intercepted data packets.
Enforce strict decoupled architectural boundaries (ATK-03) where `simulator/` never imports `attacks/`, wiring attacks exclusively in the composition root (`simulator/run_scenario.py`).
Output: Standalone `attacks/` package, duck-typed `AODVNode` adversarial hooks, dynamic intermediate-node attacker placement, scenario config `scenarios/e2_blackhole_30n.json`, and boundary validation unit tests.
</objective>

<threat_model>
- Architectural Boundary Leak: Core simulator modules (`simulator/aodv.py`, `simulator/radio.py`, `simulator/metrics.py`) must NOT import from `attacks/`. If any simulator module imports `attacks/`, the simulator ceases to be attack-agnostic and clean baseline runs are compromised.
- Non-Interception Risk: If the attacker is placed statically on a peripheral or disconnected node, it intercepts zero data flows, leading to false negatives and Gate 2 validation failures. Dynamic flow-intercept placement ensures intermediate positioning.
- Endpoint Placement Hazard: If an active CBR source or destination node is selected as the attacker, normal application traffic generation is corrupted. Dynamic selection must strictly exclude active flow endpoints.
</threat_model>
